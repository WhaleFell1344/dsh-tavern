# 当前状态与分页历史：第一阶段存储原型

对应 [设计基线](../design/current-state-and-paged-history.md)。工作分支 `codex/current-state-paged-history`。

## 本阶段完成的内容

新增 `conversation-page-store.js`，实现新格式的独立文件 Adapter。没有自动迁移原存档，也没有将现有 UI/MVU 切换到这个模块。本报告不是“酒馆万轮性能已达标”的结论。

- 可变入口仅为小型 `head.json` 指针。Head、当前状态、元数据和历史块分别保存；指针指向同一提交的不可变 Head，避免混读新历史和旧变量。
- 每个历史块最多 64 条；索引每节点最多 32 个子引用。追加只写尾部块和索引路径，跨容量边界时增长树高，不复制全部块地址。
- 每个块以内容哈希寻址并校验。未变化的块与状态复用，历史快照引用不随新写入改变。
- 冷读取直接查 Head、状态和指定页，没有完整数组占位、整档恢复或隐式 hydration；缓存仅限单次请求，不依赖跨请求热缓存。
- `commit` 原子发布追加、指定行更新和当前状态；它是底层提交接口，尚未替代领域 Foreground/MVU 提交。
- 复用 durable-file-promotion 的小文件提交和写锁；关闭按经过时间抢占活进程写锁。真实子进程测试覆盖同版本竞争写和进程在 Head 发布前退出后的恢复。

Interface：`create`、`openConversation`、`readHistoryPage`、`readState`、`commit`。分页游标固定不可变快照；翻页可以继续旧快照，不与新追加混合。记录返回值与存储隔离。跨会话游标和越界写入拒绝；损坏块明确报错。

## 操作量与耗时

执行：

```sh
node tests/experiments/conversation-page-store-performance.mjs /tmp/conversation-page-perf.json
```

真实临时目录及文件读写；每次新建读取实例，操作内部没有跨请求缓存。操作系统文件缓存未清空，不能称为物理磁盘冷启动。1000/10000 轮分别用 2000/20000 条固定大小的合成消息，当前状态固定为 50 个字段，每种规模连续测 5 次。初始化另行计时，不计入普通打开；每次提交后用新实例验证消息及变量。

| 指标 | 千轮 | 万轮 |
| --- | ---: | ---: |
| 最近 50 条及当前状态读取 | 3.80–7.95 ms | 4.62–6.64 ms |
| 追加 2 条并更新当前状态 | 54.66–60.68 ms | 70.44–72.93 ms |
| 每次读取历史块 | 2 | 2 |
| 每次追加写入历史块 | 1 | 1 |

原始数据见 [JSON](./conversation-page-store-20260927.json)。计数是不可变数据块的实际读写，不包含小型 Head 指针、写锁和 pending promotion 文件的 I/O；耗时包含这些工作。索引树增长可以增加少量索引块访问，因此不宣称严格 O(1)。

这组实验没有前台准备、模型上下文、原生 Session、浏览器、模板执行和 MVU，不能与此前 44 秒/120 秒 E2E 直接计算速度倍率。它验证的是新结构允许不读取整档就完成尾页读取和局部提交。

## 验证与限制

测试覆盖：两万行冷读取及返回值隔离、追加与状态同步发布、旧游标一致性、指定行修改、页和索引跨界、空历史、陈旧 revision 拒绝、多进程冲突、提交发布前进程退出与重试、历史状态不读正文、纯状态更新不触碰历史块，以及损坏块拒绝。

完整回归 `node bin/test-tavern.mjs`：3017 通过、0 失败、10 跳过。新增存储测试 13 项；指标采集补充了已存在块的去重读取统计，随后重跑存储测试和上述基准。生产客户端未修改，无新浏览器 E2E 性能结论。

当前原型仍有明确的接入前置项：

1. StateVersion 暂以完整不可变状态保存，未变化状态可复用；状态变化成本与 V 有关，尚未实现状态内部增量/检查点压缩。
2. Message 与 MVU baseline 的状态引用映射、任务持久化和操作 ID 去重尚未接入，不能直接替换现有 `writeChat`。底层 revision 冲突检查不等价于最终的按依赖版本校验。
3. 未实现回滚分支入口、原生 Session 投影同步、完整导出与旧档迁移。保留历史 Head 并不意味着领域回滚已完成。
4. 原型保留旧块和发布前中断留下的孤立块，没有 GC。回收必须先完成分支、任务和读取快照的引用规则。
5. 已验证的是本机文件系统上的进程中断；未完成 Windows/Android 验证和物理断电测试。新增格式尚未选为默认存储。

下一阶段先实现旧 Chat 到新逻辑记录的无损映射与只读对照，再接首屏分页和正文/MVU 提交。兼容全历史脚本的入口必须显式保留；原生会话和模板全量路径也需独立消除，不能只更换磁盘文件布局就宣称完成重构。
