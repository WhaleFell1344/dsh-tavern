# 原生存档模板历史按需读取（2026-09-27）

## 改动

服务端 ST-Prompt-Template 对原生分页存档只读取最后 200 条消息。脚本仍看到保留绝对下标及完整 length 的真实数组，访问旧下标时才从签名版本读取该楼层。同步接口通过隔离进程的独立只读管道实现，宿主仍异步读取，不增加模板的文件系统权限。

展示扫描、快照、差异计算和保存只处理已加载楼层；修改旧楼层变量仍使用原有版本冲突校验及局部写入。旧格式、未声明按需读取能力的调用者和显式完整历史展示保留原路径。数组结构不可由模板增删；真实全历史遍历仍必然读取全历史。建立索引描述符仍随楼层数量增长，本轮不声称全部 O(1)。

Helper 的按需历史基线现在可参与 MVU 增量交接：允许未加载但有历史读取凭证的旧楼层，拒绝遗漏新增楼层的增量；其 complete 标记仍保持真实含义。

## 验证

使用独立 DSH、Chromium、官方 MVU、固定模型及合成原生存档，未使用用户存档。所有性能运行与构建、单元测试错开。

- 修改前：`run-sDE2k2`，100 轮严格打开断言失败，模板初始化触发完整 Chat 读取。
- 修改后：`run-VjfRvl`，100 轮严格打开通过。
- 修改后：`run-5cZlJv`，10,000 轮、19,999 条消息、391,573,697 字节。首屏只响应末尾 48 条（793,702 字节），没有自动 fullView、初始化旧历史请求或初始化完整 Chat 读取。点击到正文 10,852 ms；状态栏就绪 38,650 ms。严格断言为打开后采样窗口，不代表后续所有操作均无完整读取。
- `run-lgTRhA`：同规模存档，重新结算一次通过，重启后变量持久化核对通过。状态栏 38,746 ms；浏览器 MVU 完成到持久化 6,482.1 ms；到界面可见 8,971.8 ms；持久化提交阶段 303.4 ms。点击重新结算到提交模型请求 54,005 ms，点击到可见总计 85,831 ms。该长档样本是重新结算（append=false），不是万轮下追加新一轮的性能证明；运行前的小存档追加游玩也通过。
- 真实隔离模板引擎测试：10,000 条逻辑数组访问旧下标只读取该楼层一次；原生存档旧楼层变量修改、保存及磁盘核对无完整 Chat 读取。
- 覆盖普通完整上下文、增量保存、异步保存回执、本地修改、刷新、切换回完整历史、管道较大响应及 MVU 增量缺失楼层保护。

针对性回归：162 项中 161 项通过、1 项因未配置 `DSH_BOOT_MODULE` 跳过、0 失败。客户端生成文件检查、模板服务端及浏览器产物构建、`git diff --check` 通过。

本地原始结果：`output/e2e-gameplay/run-5cZlJv`、`output/e2e-gameplay/run-lgTRhA`（未提交大体积原始产物）。后者包含浏览器 CPU profile 与分段服务端记录。

## 尚未达标及下一步

本轮消除了模板初始化整档读取和万轮本次结算超时，但没有达到万轮快速打开、快速结算的目标。浏览器采样主要为 idle，不能据此将 39 秒归因于浏览器计算或磁盘；仍需对启动资源等待及服务端请求做关联采样。

结算记录仍有 13 次完整读取，具体调用包含 `retrySettlement`、`runSettlement`、后台任务 `begin` / 执行准备、世界书上下文读取、通用写入、`saveDelivery`、`readSettlementChat` 和结算后处理。391 MB 超过当前完整 Chat 缓存上限，导致这些路径重复解析。同一记录已提供调用栈，应将后台任务改成轻量任务头与目标楼层读取，继续保留生命周期、版本及事务冲突保护，不能靠扩大缓存宣称解决。

单次合成、三字段变量性能不能代表复杂人物卡或万字段变量。专用管道已在 macOS 的真实隔离进程验证，Windows 尚未实机验证。
