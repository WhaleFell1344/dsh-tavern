# 原生存档：事务写入与冷读取优化

本轮继续优化新格式的实际运行时路径，没有转换用户旧存档。基础提交为 `c9c4292d`。

## 已定位并修复的成本

最小复现只修改同一消息的 20 个标量变量，却产生 209 次块文件写入，耗时约 2095 毫秒。适配器每改一个字段都立即写树的祖先节点，消息变量与当前世界又各做一次；很多持久化的根只存在于事务中间。

现在事务先在私有内存中构造树，只保存最终头部、消息和世界引用能到达的块。新增块分组为不超过 64 KiB、128 个条目的不可变数据包，通过硬链接保留直接按内容哈希读取的路径。数据包内容先同步，再同步引用目录，最后原子发布 Head；不会提前确认成功。大标量仍单独保存。不支持硬链接的文件系统回退到原有单块文件写法。

数据包读出时逐项校验内容哈希，使用有大小限制的不可变块缓存。原有单块文件继续可读，旧 JSON/journal 路径没有自动转换。文件包并不改变消息分页和当前状态树的逻辑结构。

冷读取也有调整：

- 按楼层读取直接定位分页和消息引用，连续楼层共享页读取；不会先物化整个 Chat。
- 结算投影跳过历史 checkpoints；配置读取只取指定字段。
- 新消息页附带紧凑会话摘要，状态读取不再获取全部历史变量。没有摘要的早期原生页逐行回退，保留原有语义。
- 查询 Head/版本不再顺带读末页。完整 Chat 读取仍返回相互隔离的完整值；请求内部复用重复块，避免同一历史变量被反复读盘。

100 轮重复重算还复现了另一个瓶颈：历史模板补处理与 `settlement.retry` 的整档写入竞争，第三次重算报 messages 冲突。重算入口现改为精确 revision 的局部 patch；冲突后重新读取并验证最新正文、后台活动及基线，最多重试五次。并发显示更新被保留，若正文已改变则拒绝重算旧目标。

## 测量

底层探针：`node tests/experiments/native-storage-performance.mjs --rounds=10000`。这是实际文件系统和生产存储适配器测试，生成 20,000 条消息、20 个额外变量字段，不含浏览器或模型。

| 操作 | 本轮实测 |
| --- | ---: |
| 万轮合成档首次构造 | 25.95 秒 |
| 冷读取末尾 100 条 | 12.8 毫秒 |
| 冷读取紧凑会话摘要 | 68.8 毫秒 |
| 已打开档更新 20 个变量 | 117.8 毫秒，8 次文件写入、12 个硬链接 |
| 明确请求完整档案 | 3011.3 毫秒 |

未打包版本在相同万轮探针的首次构造阶段超过 366 秒，随后终止测试；它没有产生打开或结算时间，不能把该数值称作打开耗时。会话摘要仍需要全部轻量行，完整读取仍随输出量增长；只有尾部选择真正按所选范围读取。

真实浏览器使用固定模型输出、官方 MVU、隔离 DSH。100 轮、2 个额外字段、每条合成正文重复 60 次，连续三次重算，完整通过（`run-bBOE2X`）：

- 浏览器 MVU 完成到原生持久化：744.0、738.2、718.2 毫秒。
- commit 阶段：210.7、214.5、184.8 毫秒。
- 服务重启后仍能打开，磁盘格式与当前世界变量一致。

此前小样本一次测得对应阶段约 3400 / 2297 毫秒；样本轮数及系统负载不完全相同，以上不是严格随机化 A/B 比较。1000 轮在完整回归同时运行时完成三次结算，打开到状态栏约 4348 毫秒，MVU 完成到持久化约 1866–2063 毫秒。该次最终重启断言把合法的历史显示补处理误判为消息变化，已修正为仅忽略四个明确的派生模板字段，仍逐项核对剧情、变量、MVU 和其他扩展数据。

修正验证断言后，最终 1000 轮测试完整通过（`run-rq9Y3N`）：打开到状态栏约 5820 毫秒，MVU 完成到持久化 672.4 毫秒、commit 193.1 毫秒，服务重启后的剧情和变量保持一致。启动阶段与两套功能 E2E 同时运行，不能据此作独占冷启动性能结论。

## 万轮真实浏览器尚未通过

另一次使用 10,000 轮、约 175 MB 合成 Chat 的真实浏览器测试，120 秒内仍未完成 MVU 初始化（`run-ZQ2CuS`）。会话正文已显示尾部，但状态栏没有恢复到预期金币值，未进入结算采样，不能宣称万轮 E2E 通过。

日志记录 10 次 `cache-oversized`：完整 Chat 估算约 307 MB，超过 256 MiB 缓存上限。现有初始化仍要求完整 Chat/Helper 上下文，触发重复全量物化。底层可以快速读尾页，不代表这些上层调用已经改为尾页协议。提高缓存上限不能解决这种历史长度依赖。

下一阶段应改造 MVU 初始化、Helper 上下文与前台打开的消费接口，让当前变量和历史分页分别读取；涉及历史任意楼层的兼容 API 必须明确按需获取，不能悄悄返回截断的数据。

## 正确性验证

完整回归：3080 通过、0 失败、10 跳过。随后 Head 专项及最终存储测试 25 项通过。最终完整游玩 E2E（`run-KPdxYl`）和 Helper/双页面/重启 E2E（`run-fau3LI`）均通过，另有最终千轮浏览器 E2E 通过。新增验证包括：

- 最终树写入数量上限、冷读跳过无关历史大值、连续楼层共享页读取。
- 缓冲刷盘时真实子进程被 SIGKILL，重启保留完整旧状态，重试后完整提交。
- 数据包哈希校验、独立读取器恢复、旧单块去重、对象隔离、大字段独立文件与硬链接不支持时回退。
- 重算遭遇显示更新后重试；遇到最新正文改变则拒绝。

测量摘要保存在同目录 JSON；浏览器截图、完整日志和 trace 保存在 `output/e2e-gameplay/`。测试只使用隔离合成资料。本轮没有推送发布。
