# 重新结算入口与世界书窗口读取（2026-09-27）

## 改动与边界

重新结算先尝试原生末尾 48 条窗口，保留绝对楼层坐标、存档版本 CAS、最新轮次及后台忙碌检查。成功后返回窗口视图，不把部分 Chat 作为完整视图投影。窗口没有可重试的助手消息、旧时间线需迁移、旧格式或配置需采用时，继续原完整路径。并发 CAS 失败仍重新读取并校验。

服务端模板运行时声明 `historyContext: 'session'`，表示历史由自身会话上下文提供。世界书投影不再为它构造完整 transcript；该字段原本不参与服务端 prepareContext，模板已有的绝对楼层访问仍由按需历史数组提供。未声明能力的其他运行时继续收到完整 transcript。

后台世界书读取使用窗口中可以确认的最新变量（或原虚拟前台输入）。窗口找不到变量时保留完整读取，避免把较早的有效变量误当作不存在。世界书绑定、宏状态和随机状态等仍取完整头部；不截断模板能够主动访问的历史。

## 验证

100 项针对性测试全部通过，涵盖世界书投影、真实隔离模板引擎、原生模板持久化、后台任务及 MVU 宿主适配。新增测试断言：声明能力的运行时不会触碰旧消息，变量作用域不变；旧运行时仍收到完整 transcript。

仅重新结算入口修改的诊断运行 `run-pVIJEN` 通过万轮严格打开、重新结算及重启变量核对，总耗时约 32.2 秒。最终合并世界书优化后的数据在下文记录。

E2E 使用独立 DSH + Chromium + 官方 MVU + 固定模型、10000 轮/19999 条消息/约 391 MB 三字段合成档。长档性能测试为重新结算末轮（append=false）；小档追加游玩单独通过，不能作为万轮追加性能的证明。计时期间不运行构建或单元测试，结果是本机单次样本。
