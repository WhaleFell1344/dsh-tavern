# 旧存档兼容、迁移与反向恢复

旧用户不应因存储结构升级重新开档。本阶段把兼容读写接进现有 `createChatJournalStore`，不改变上层 Chat、MVU、Helper、原生会话和回滚的数据契约。

## 兼容策略

两件事分开：底层分块存储可以升级，旧玩法的数据模型无需同时重写。旧 Chat 的所有字段作为完整 JSON 契约保留在不可变树中，包括未识别的扩展字段、历史变量、MVU 基线与未完成交付、timeline、原生提交映射、脚本作用域和展示标记。

这是 `legacy-compatible-json-v1` 兼容格式，不把旧档强行转换成 `conversation-state-v2` 的新任务模型。原有业务入口继续获得完整、隔离的 Chat 对象。需要完整历史的兼容读取仍会物化完整对象，不能宣称已经获得新领域接口的万轮打开性能。

- 没有格式标记：继续使用旧 JSON / snapshot + journal。
- 有已激活的兼容标记：现有读写入口自动路由到新存储，无需继续设置环境变量。
- 未知或损坏的格式标记：明确报错，不猜测格式或覆盖文件。
- 转换尚未成功：原存档继续可读写，未激活的部分转换结果不会被当作有效存档。
- 转换已经成功后新存储损坏：明确报错，不能静默读取迁移前备份冒充最新进度。

## 转换过程

1. 通过与所有正常 Chat 写入共用的跨实例/跨进程文件锁，串行化同一存档的转换与写入。
2. 读取旧 JSON 或恢复 journal，捕获源版本。
3. 在独立目录建立分块树和 Head；旧文件保留。
4. 从实际持久化记录完整还原，并逐字段、顺序校验 JSON 与源结果一致。
5. 再检查源版本没有变化，最后原子发布 `storage-format.json`。
6. 重新打开、继续写入和历史版本查询均通过同一现有 Chat 接口。

转换中退出进程、磁盘错误或源变更都不会切换权威数据。重复尝试同一源版本可以复用完整或部分不可变数据。失败版本在当前进程内有限缓存，避免每次读取都重复进行失败转换；显式重试可使用迁移命令。

该协议协调使用新版存储入口的写入者。不要同时用不认识新格式的旧程序写同一资料目录；降级应先执行反向恢复。

## 启用与工具

生产入口已经支持识别已迁移的存档，但本次没有默认开启对全部旧档的自动转换，也没有修改用户实际存档。

受控开启首次完整读取时的自动转换：

```sh
DSH_TAVERN_COMPATIBLE_STORAGE=1 node bin/dsh-tavern.mjs start
```

环境变量需传入实际运行插件的宿主进程；已运行的 Desktop 宿主需要在其启动环境设置并重启。该开关只控制自动转换，关闭后仍可读写已经转换的存档。

也可按存档执行：

```sh
node bin/migrate-conversation-storage.mjs --data /path/to/tavern-data --chat CHAT_ID
```

转换失败返回 `status: legacy` 并以状态码 2 退出；读取原存档的能力保留。未知格式或已激活数据损坏以错误退出。

## 反向恢复

```sh
node bin/migrate-conversation-storage.mjs --data /path/to/tavern-data --chat CHAT_ID --restore-legacy
```

反向恢复导出当前进度和迁移后产生的每个存储 revision，生成旧格式 snapshot + journal，再验证当前数据，最后切回旧格式。它不是直接恢复迁移前备份。

- 原生旧格式读取器可以读取新增进度和新增历史版本。
- 反向恢复过程中断时，新存储仍是权威；重试会从已导出的 revision 继续。
- 恢复后持久标记为旧格式，避免自动转换立即将其再次升级；显式迁移命令可重新转换。
- 保留不可变历史用于校验及历史查询；删除整个存档时一并清理新旧数据。

反向恢复是显式全历史操作，可能较慢、增加磁盘占用；正常结算不执行它。

## 已验证与发布门槛

自动化覆盖：旧 JSON、journal 帧、源字段无损、完整/轻量投影一致、通过现有 ChatPersistence 更新、变量结算写入、历史消息截断、重启、迁移失败继续写入、迁移时源变更、跨实例写锁、真实子进程中断与死锁恢复、取消提交、损坏与未知格式拒绝、删除清理、反向恢复的新进度与回滚点、重复迁移、稀疏数组及特殊字段名。

验证结果：完整回归 `node bin/test-tavern.mjs` 为 3066 通过、0 失败、10 跳过；随后补验反向导出中断与真实 CLI 调用，兼容专项 14 项全部通过。`node --check tavern-plugin/lib/index.js` 与 `git diff --check` 通过。

这证明了存储契约兼容，不等于所有真实人物卡与宿主版本的 UI E2E 认证。默认开启全面自动转换前，仍须验证真实档的继续游玩、待完成 MVU 恢复、回滚/撤销、Helper/EJS 与原生会话恢复；一旦发现不能安全转换的档案，应继续使用旧格式，不要求用户丢弃或重开。
