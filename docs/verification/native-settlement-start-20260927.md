# 后台结算启动的局部写入（2026-09-27）

## 实现

结算调用后台任务 `begin` 时，以内部 `reuseSnapshot` 选项复用已经读取的完整快照。`agent.begin` 仅对时间线元数据执行原有领域转换，省去历史消息和旧检查点的复制，通过原存档版本 CAS 写入差异。返回的任务快照保留完整消息、历史检查点及最新存档版本。

这一选项不改变默认 begin 契约。具备幂等 requestId 的请求、旧时间线迁移或缺失检查点数组的状态继续走原路径。CAS 冲突后重新读取权威状态，并重跑压缩、忙碌和任务合法性检查；不会把过期快照的正文或变量覆盖回去。内部复用选项保留调用者已有消息对象，不向外暴露存储缓存。

前台世界书查阅记录的交接只使用最新助手轮次、开场标记及重生成映射，改读会话摘要；查阅资料仍来自原前台 Session 中已完成的工具结果，完整世界书模板上下文不在本轮截断。

## 性能与限制

使用独立 DSH + Chromium + 官方 MVU + 固定模型；合成档 10000 轮、19999 消息、391573697 字节、三字段变量。测试为重新结算末轮（append=false），不代表万轮追加游玩或复杂人物卡性能。性能测量期间不运行构建和测试。

本轮仍保留 retrySettlement、runSettlement、当前世界书及 MVU 工作副本的完整读取，未宣称整体 O(1) 或快速打开已经达标。

最终针对性测试 52 项全部通过；客户端生成文件检查与 `git diff --check` 通过。
