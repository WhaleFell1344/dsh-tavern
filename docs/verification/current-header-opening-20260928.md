# 首屏元数据读取与诊断点查询优化（2026-09-28）

## 诊断

上一轮宿主统计重放优化后的万轮状态栏就绪时间为 4.960 秒。新采样 run-iq3suy 测得 4.369 秒；完整冷进程 CPU 采样中，历史页返回值复制约 1.30 秒，块解码约 0.73 秒。这些 CPU 数字包含首屏之后的工作，不能全部当作首屏等待。

调用栈证明 `readSessionState` 的全历史摘要加载被多种只需头部字段的检查触发。分页正文并没有被重新完整物化为 Chat，但摘要包含历史 MVU 回执，逐页读取 / 复制仍昂贵；超过摘要缓存上限后还会反复发生。只优化候选同步的中间样本仍为 4.538 秒，说明该路径不是唯一来源。

严格 E2E 的红例 run-Zc07rV 在状态栏约 3.166 秒时发现 1 次全历史摘要遍历。补充调用栈 run-0IydZr 定位到 `getConversationWritingSkills`；状态栏之后的诊断采集也会调用同一个全历史摘要加载器。因此最终断言覆盖首屏就绪和随后 3 秒空闲阶段，而不是把工作推迟到计时终点之后。

## 改动与兼容边界

- 新增只读 Task State reader，任务同步、活动查询、启动恢复检查及后台会话筛选只读取所需头部字段。原有完整 Session State 接口和返回值隔离不变。
- Skill 身份判断、开关目录读取所需配置字段，不枚举历史消息。Skill schemas、工具定义与提示词规则没有改动。
- 自动压缩处于 manual 模式且没有运行中任务时，只检查元数据；启用自动压缩、手动执行以及恢复未完成压缩仍走原来的完整判断和执行路径。
- MVU 恢复先看时间线活动，只有 pending 状态才加载历史回执以判断是否恢复提交。真正恢复重生成、后台任务，以及旧版 foreground-completed 正文迁移仍保留原读写路径。
- 显示诊断复用既有楼层索引读取目标记录。写入索引时记录各前缀的推断轮数、最大显式轮号，以及是否与诊断接口的选楼规则完全一致；保留“首个匹配楼层”和“最大轮号”的旧语义。推断轮号不一致时回退完整摘要读取。
- 新增可选 displayIndexRevision 标记，与 head 一起原子发布。旧索引缺少元数据或旧写入器留下过期元数据时回退；变量更新不能将未经验证的元数据标记为有效，后续正文索引重建才能修复。旧存档可以继续使用，不要求迁移后才能打开。

这是对现有读取路径和可选索引的扩展，没有另立存档格式，也没有截断历史。头部时间线本身仍可能随操作数量增长；实际历史恢复、旧版兼容回退仍允许读取历史，不能宣称所有路径 O(1)。
