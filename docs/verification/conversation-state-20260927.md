# 当前状态与分页历史：领域事务阶段

本阶段为独立的新格式后端增加正文提交和 MVU 结算事务。尚未替换产品入口，不代表浏览器打开或真实游玩已达到目标性能。

## 写入规则

`createConversationState({store})` 把存档分成当前世界状态、分页消息、可寻址操作记录。上层调用者负责模型和脚本执行；领域层只接受准备好的正文、submission 和完整世界状态，不执行外部副作用。

- `commitForeground`：校验 branch/story/world/lifecycle 基线，原子追加用户与助手正文、状态基线引用、待结算任务和幂等回执。旧待办被标记为 superseded。正文提交不等待 MVU。
- `submitSettlement`：先持久保存模型提交内容，不修改世界状态。
- `prepareSettlement`：持久保存上层计算好的完整结果。相同 operation ID 不允许替换为不同效果。
- `commitSettlement`：检查任务仍属于当前分支和目标正文版本，一次发布世界状态、消息状态引用、完成回执。重启后的重复调用返回原回执。
- `failSettlement` / `cancelSettlement`：保留正文。失败可显式重试或继续下一轮；取消后不能应用先前保存的效果。
- `readMessageState`：按位置读取单条消息引用的前/后状态，不恢复完整 Chat。

并发冲突只重试短事务，不重新运行模型或脚本。无关 metadata 更新不使结算基线失效；分支、世界、生命周期或目标正文变化会阻止过期结果落地。底层 store 是受信任的内部接口，不能绕过领域层任意修改正文后还假定任务关系有效。

## 操作索引

Head 只增加 `recordRoot` 引用。操作 ID 经 SHA-256 路由到持久哈希树；修改只复制有限索引路径。回执不会被塞入持续增大的 Head，也不通过扫描消息寻找。旧 snapshot 保留当时的回执视图，回执与正文/状态共享同一次 Head 原子发布。

这是用历史长度换空间、避免每轮全历史工作的基础，不承诺严格 O(1)：索引路径、当前状态大小、消息页大小仍有成本。不可变旧节点和回执暂未回收，空间维护另需实现。批量写入按哈希路径合并，避免为每个键重写同一索引分支；但一次性生成数万条回执仍涉及大量小文件与同步写盘，导入成本需单独优化。

## 验证

定向测试覆盖：2 万条消息下的正文与结算页面访问量、重启恢复、重复提交、丢失响应、不同内容复用操作 ID、失败继续、取消、过期效果、并发 metadata 更新、同基线并发正文、历史状态引用、索引快照、损坏/中断/跨进程存储行为。

验证结果：`node bin/test-tavern.mjs`：3042 通过、0 失败、10 跳过；共 3052 项测试。原有客户端代码未修改。

性能脚本：

```sh
node tests/experiments/conversation-state-performance.mjs docs/verification/conversation-state-20260927.json
```

测量使用 1000/10000 轮正文及对应历史操作记录，固定当前状态约 8 KB；每组连续三轮，每轮重新创建读取实例。OS 文件缓存可能命中，未清空磁盘缓存。各阶段含持久化写入，夹具构建与历史回执生成不计入正常游玩。

实测范围（每组 3 次，单位 ms）：

| 历史轮数 / 回执数 | 打开末尾 50 条 | 正文提交 | submission 持久化 | 准备结果持久化 | 最终结算落盘 |
| --- | --- | --- | --- | --- | --- |
| 1000 / 2000 | 2.1–5.8 | 161.7–181.0 | 107.3–112.6 | 96.7–108.3 | 124.1–132.2 |
| 10000 / 20000 | 2.2–6.7 | 188.8–211.0 | 108.8–135.7 | 108.3–113.1 | 139.7–146.2 |

两组每次完整序列都读取 8 次消息页、写入 2 次消息页（同页可在不同事务重复读取），没有恢复整段历史。万轮组从 submission 持久化到最终落盘合计约 360–391 ms，不包含上层计算效果的耗时。历史规模增加 10 倍，索引访问略增；这是本次固定数据形状的 3 次样本，不是严格延迟上界。

详细时间和 I/O 记录见同名 JSON。它不包含模型、脚本、模板、原生 Session、浏览器传输与渲染，不可换算为端到端耗时。

## 下一道接入门槛

当前格式 `conversation-state-v1` 与旧档无损影子格式 `legacy-chat-mapping-v1` 分开。领域接口明确拒绝直接写入影子档，避免让旧导出校验失效后误当成迁移成功。

仍需完成：现有正文/MVU 调用入口的领域适配、旧档 timeline/native delivery 到新任务的转换、回滚/最后一轮替代、原生 Session 投影和恢复、Helper/EJS 显式全历史兼容路径，以及跨页面通知。之后才能做真实存档迁移和 UI E2E，决定默认切换。
